## Delivered scope

Active creators with completed marketplace onboarding get **Your portfolio** navigation and `/portfolio`. They choose separate public text: display name, headline, about and up to six curated HTTPS work links with titles and optional short descriptions. Save draft accepts incomplete text/zero links; publishing requires a valid address, complete text, one to six titled HTTPS links and an actively checked public-sharing consent. There is no automatic publication or private-profile import.

`/portfolio/preview` is an owner-only preview of the **saved draft**. It does not publish or include unsaved form edits. Publish atomically saves submitted fields and replaces the public snapshot; later draft saves do not change that snapshot. `/creators/[slug]` displays only that chosen snapshot. Unpublish removes it from new server requests, preserving the draft and reserved address. A current suspension or withdrawn profile completeness also hides it. Re-activation with restored completeness can make an existing publication visible again; publication state remains separate from membership.

Addresses use 3–40 lowercase letters/digits/hyphens, starting and ending alphanumerically. A chosen draft address is unique; before first publication its owner may change it. First publication permanently locks/reserves that address, including after unpublish. No deletion/reassignment or rename flow is introduced. Optimistic revision checks reject stale edits/collisions with `PT409`, never `40001`.

The editor explains public sharing, permission to share work, permanent addresses, saved-only preview and draft/public separation. Fields and structured work rows survive rejected actions; owner-read and mutation network uncertainty return preserved drafts with a refresh/check-state message. The consent checkbox resets unchecked after action results. Unpublish bypasses incomplete form validation. Share URL is selectable and the published page opens separately.

No avatar/image/upload, location, follower metrics, contact email, collaboration evidence, OAuth, analytics, public directory, custom domain/site builder, verified-results claim or payment behavior is added. External links are labelled and opened with safe link attributes; no embeds or remote content fetches occur. Users must choose work they may share. Existing member-profile and Storage access stay private.

## Security and publication boundary

Migration `20261121143350_phase_7_creator_portfolios.sql` (CLI-created) is **applied to DEV and immutable**, SHA256 `94B178818551D2352614100929B4C323A40BBFE32ED14FEF0389D98AAE25EB86`. Parent reviewed/applied it, aligned its exact ledger version and regenerated actual `src/lib/database.types.ts`. No credentials or privileged portfolio client were added.

- `creator_portfolios` is a distinct owner/draft/published store with RLS, no anonymous/authenticated base SELECT or DML grants. Existing non-login, non-inheriting, non-BYPASSRLS executor holds only needed access. Owner commands independently check current complete creator membership, lock the owner then portfolio row, validate fields, consent and expected revision, and return owner-only state. The owner lock serializes publication against membership suspension.
- Public invoker RPC `creator_portfolio(slug)` delegates to exactly one safe private projection. Anonymous schema USAGE permits name resolution, but **only `marketplace_private.public_portfolio(text)` is executable by anon** across the private schema; editor/command/validator and all older helpers remain denied. The public DTO has exactly `display_name`, `headline`, `about`, `works`; work items have only `title`, `description`, `url`. No owner UUID, Clerk ID, membership record, revision or draft is exposed.
- Public rendering uses a publishable-key **anonymous** client, even for signed-in visitors; ordinary owner actions use the current Clerk JWT. Server-only services parse strict DTOs. Public route is dynamic, uses no-store fetching and no shared data cache; response configuration requests private/no-store and `X-Robots-Tag: noindex, nofollow, noarchive`, with noindex metadata. Every new read checks publication/current membership/completeness.
- Noindex is an indexing request, not confidentiality or erasure. Unpublish/suspension cannot remove copies or an already-open page; the editor says so. Nothing promises public work is verified or external links stay available.
